# ADR-67: Language Design Charter — Rust's Safety Model and Go's Simplicity and Concurrency

- Status: Accepted
- Date: 2026-11-12
- Associated Milestone: M0.1 ([design charter](../plan.md#2-language-design-charter))

## Background

ADR-1 through ADR-66 advanced by adding built-ins and runtime micro-optimizations. This produced handwritten container families for particular element types (`vec`, `vec[string]`, `vec[f64]`, and two maps), nine predefined result enums, and many global built-ins. The approach grows linearly and does not yet provide important Go and Rust capabilities such as concurrency, interfaces, package management, static borrow checking, generic containers, closures, and iterators.

## Decision

Adopt [the design charter in the plan](../plan.md#2-language-design-charter), including these ten rules:

1. Implement containers, result types, and iterators generically; do not add handwritten per-type families or predefined result enums.
2. Retain only primitives that cannot be expressed in the language as compiler built-ins; move the rest to standard library methods.
3. Check borrowing and move safety statically; runtime checks are not a fallback.
4. Infer lifetimes by default.
5. Use structured scopes to spawn ordinary functions without function coloring.
6. Use `Result[T, E]` and `?` for errors; reserve `panic` for invariant violations.
7. Keep development and release semantics identical.
8. Link runtime components only when used.
9. Specify features before implementation.
10. Support claims with reproducible evidence.

## Consequences

- Changes to these rules require a separate ADR.
- Existing built-ins and container families are to migrate to generic standard-library implementations in M1; see [ADR-68](0068.md) for the freeze.
- Go and Rust are the primary comparison targets.
