## 2. 本会话完成的功能

1. **ADR-0236 rung 1 — `&[T]` 切片**：`TyKind::Slice(ElemId)`；C 端一个
   `ae_slice{data,len,elem_size}`；调用点可由整个 vector（`&v`）、整个
   array（`&a`）或切片参数转发构造；`len`/索引/`for` 按元素规则读
   （Copy 值、string 视图、`&vec`/`&Struct` 视图）；只读、调用期有效；
   元素切片/`push`/本地绑定/返回均拒绝；解释器用快照模型。
2. **差分 fuzzer 切片形状**：i64 切片（vector/array 源、参数转发）、
   `&[string]`、`&[FuzzTag]`（owned 元素字段投影）、`&[vec]`；四模式对比。
3. **rung 3 — 子切片**：`&v[start..end]` / `&a[..]` / `&slice_param[..]`；
   共享语法 `split_range_argument` 找顶层 `..`；resolver 解析两端读取；
   lowering 要求两端为 i64 标量表达式；运行时 `ae_slice_sub` 检查
   `0 <= start <= end <= len`（调用点陷阱 "slice range out of bounds"）并
   偏移 data/缩短 len；`len`/索引/`for` 无需改动；解释器同界校验、同陷阱
   位置。缺界/非整数界/`&mut`/字段接收者/元素切片/moved 源均有诊断；空 vector
   的整窗 `&empty[0..0]` 直接返回切片本身，避免 NULL 参与指针运算。
4. **语法单测**：`sub_slice_ranges_split_at_the_top_level` 锁定
   `&v[1..3]`、`&a[start..end]` 与 `&w[i]` 的切分行为。
5. **rung 3 额外审计（用探针验证，未固化为夹具）**：切片参数自身的
   `len(s)` 作端点、`&[T; N]` **数组参数**窗口、`while` 循环里的动态端点
   `&v[i..i+1]`（越界时 C 与解释器陷阱位置/文本相同）、闭包捕获 vector
   上的 `&v[1..3]`——三种执行路径（MIR C、tree C、`--interp`）结果一致。

- Bash 工具会处理 `\n` 转义：用 Python heredoc 往 Rust 文件追加测试时，

  `tests/execution.rs` 里 3 处 `join("\n")` 已修正，改动时留意。

  时必须保留 `\r\n`，否则整文件 diff。
