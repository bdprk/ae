## 2. 本会话完成的功能

1. **ADR-0236 rung 1 — `&[T]` 切片**：`TyKind::Slice(ElemId)`；C 端一个
   `ae_slice{data,len,elem_size}`；调用点可由整个 vector（`&v`）、整个
   array（`&a`）或切片参数转发构造；`len`/索引/`for` 按元素规则读
   （Copy 值、string 视图、`&vec`/`&Struct` 视图）；只读、调用期有效；
   元素切片/`push`/本地绑定/返回均拒绝；解释器用快照模型。
2. **差分 fuzzer 切片形状**：i64 切片（vector/array 源、参数转发）、
   `&[string]`、`&[FuzzTag]`（owned 元素字段投影）、`&[vec]`；四模式对比。
3. **rung 3 — 子切片**：`&v[start..end]` / `&a[..]` / `&slice_param[..]`；
   共享语法 `split_range_argument` 找顶层 `..`；resolver 解析两端读取；
   lowering 要求两端为 i64 标量表达式；运行时 `ae_slice_sub` 检查
   `0 <= start <= end <= len`（调用点陷阱 "slice range out of bounds"）并
   偏移 data/缩短 len；`len`/索引/`for` 无需改动；解释器同界校验、同陷阱
   位置。缺界/非整数界/`&mut`/字段接收者/元素切片/moved 源均有诊断；空 vector
   的整窗 `&empty[0..0]` 直接返回切片本身，避免 NULL 参与指针运算。
4. **语法单测**：`sub_slice_ranges_split_at_the_top_level` 锁定
   `&v[1..3]`、`&a[start..end]` 与 `&w[i]` 的切分行为。
5. **rung 3 额外审计（用探针验证，未固化为夹具）**：切片参数自身的
   `len(s)` 作端点、`&[T; N]` **数组参数**窗口、`while` 循环里的动态端点
   `&v[i..i+1]`（越界时 C 与解释器陷阱位置/文本相同）、闭包捕获 vector
   上的 `&v[1..3]`——三种执行路径（MIR C、tree C、`--interp`）结果一致。
6. **泛型切片**：`fn size[T](v: &[T])` 合法；调用显式写类型参数
   （`size[i64]`/`size[string]`/`size[vec]`，推断属 P2.5.2），`len`/`for`/
   子窗口在每个实例化上一致；`tests/run/generic_slices.ae` 固化 i64、
   string、嵌套 `vec` 与整个 array 的实例化，`generic_slices_match_across_backends`
   四后端对比并锁定缺类型参数的拒绝。
7. **rung 2 — 切片元素 place 借用**：`&items[0]`/`&rows[len(rows)-1]`
   （切片参数内）可传给 `&Struct`/`&vec`，与向量元素借用同一 `BorrowAs`
   地址语义；string 元素同样拒绝；`tests/run/slice_element_borrows.ae`
   四后端固化 owned struct 与嵌套 vec 元素。
8. **rung 4 — 可变切片 `&mut [T]`**：调用点 `&mut v` 或窗口
   `&mut v[start..end]`（必须是 `var` 向量、语句内无冲突借用），callee 用
   `len`/`m[i]`/`for` 读、`m[i] = x` 写；C 走新 `ae_slice_mut_at`，解释器用
   `Val::SliceMutRef{owner,start,len}` 写回调用帧（窗口带 start）。仅 Copy
   元素；字段接收者/转发/本地绑定/返回/owned 元素写入/元素级借用/开区间
   均有诊断。`tests/run/slice_mut.ae` 四后端固化（含窗口写入）。
9. **固定数组迭代**：`for x in a` 接受数组变量与 `&[i64; N]` 参数，长度取
   类型常量（无运行时 `len`），元素按 Copy 值绑定（Copy 结构体可直接读
   字段），支持 `break`/`continue` 与嵌套；数组在循环期间登记容器借用，
   循环体内写元素被拒（`cannot modify 'a' while it is borrowed`，补上了
   数组 store 之前漏掉的借用检查）。`tests/run/array_for.ae` 四后端固化。
10. **数组 Copy 语义**：`let copy = a;`（含 `&[i64; N]` 参数）、
    `a = b;` / `a = [..];` 整体赋值（长度/元素类型校验，字面量先全部求值
    再写，故 `a = [a[1], a[0]]` 可交换）、`a[i] += v;` 复合写（索引只求值
    一次，含带副作用索引）。`tests/run/array_copy.ae` 四后端固化，负例
    覆盖不可变、借用中、长度/类型不匹配与 bool 复合写。

## 5. 坑与注意（本会话踩过）

- Windows MinGW **没有 ASan/UBSan 运行时**；`--sanitize` 必须在 WSL 里跑。
- `tests/ui-json/*.ae` 由 `.gitattributes` 固定为 LF，但本地旧工作树可能残留
  CRLF；用它生成 JSON 期望会写入 CRLF 字节偏移，Windows 本地通过、Linux
  CI 失败。改这些期望前先确认工作树无 `\r`（`grep -l $'\r' tests/ui-json/*.ae`），
  或用 LF 夹具重新生成。
- Bash 工具会处理 `\n` 转义：用 Python heredoc 往 Rust 文件追加测试时，
  字符串里的 `\n` 曾变成真实换行并拆行。修复方式是改用 Edit 工具；
  `tests/execution.rs` 里 3 处 `join("\n")` 已修正，改动时留意。
- 文档（尤其 `docs/implementation-ledger.md`）是 **CRLF**；用 Python 重写
  时必须保留 `\r\n`，否则整文件 diff。
- 后台 `cargo test --test snapshots` 曾因残留的 `ae.exe`/`cargo.exe`
  跑了 790 s；单独跑各 runner（types/resolve/ui/json_ui/hir/run）可分辨。
- 不要 `git add -A`；按仓库规则显式路径提交。
